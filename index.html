Algorithms & Strategy

1. Main Control Algorithm — Finite State Machine

The robot is controlled using a finite state machine (FSM). Each state represents a high-level behavior, and transitions are triggered by sensor readings, timers, or navigation conditions. This design keeps the behavior predictable, modular, and easy to debug.

Global FSM Structure (Pseudo-C)

while (match_running) {
  update_position();
  update_state_machine();
}

2. State Descriptions

STARTUP

The STARTUP state initializes the robot at the beginning of the match. The robot starts moving forward slowly and sets its first target mineral position. During testing, if a red mineral is already detected, the robot immediately transitions to the pickup sequence.

Transition: Immediately switches to EXPLORE after initialization.

EXPLORE

In the EXPLORE state, the robot moves forward toward the current target mineral position stored in mineral_positions[]. The color sensor is continuously monitored to detect red minerals.

To correct odometry drift, the robot periodically realigns itself toward the target using the ALIGN_TARGET_POSE state.

Transitions:

  • Red mineral detected → APPROACH_MINERAL
  • Periodic timer → ALIGN_TARGET_POSE

ALIGN_TARGET_POSE

This state aligns the robot toward a target position (either a mineral or the home box). The desired heading is computed using the robot’s current 2D pose and trigonometric calculations.

Two alignment modes are used:

  • Full turn: For large heading errors
  • Smooth arc correction: For small adjustments while moving

Transition: Returns to EXPLORE or RETURN_HOME depending on context.

APPROACH_MINERAL

Once a mineral is detected, the robot moves forward for a fixed duration (2 seconds) to ensure the grabber is properly positioned in front of the mineral.

Transition: After 2 seconds → PICKUP_MINERAL

PICKUP_MINERAL

The pickup sequence is executed in a deterministic order:

  • Close grabber by a fixed number of degrees
  • Lift the arm upward by a fixed number of degrees

Blocking delays are used to guarantee mechanical completion before transitioning to navigation.

Transition: After pickup → RETURN_HOME

RETURN_HOME

The robot navigates back to the collection box using its estimated 2D position. The box position is stored as a fixed target, and the robot periodically realigns its heading toward it.

When the robot is close enough to the box and detects it using the ultrasonic sensor, it prepares to drop the mineral.

Transition: Near box → DROP_MINERAL

DROP_MINERAL

The robot releases the mineral by opening the grabber, moves backward slightly to clear the box, and lowers the lift arm. The target index is incremented so the next mineral can be collected.

Transition: After drop → EXPLORE

AVOID_OBSTACLE

Obstacle avoidance is a simple recovery behavior. The robot moves backward at a fixed speed and then realigns itself toward the target. This keeps avoidance behavior predictable and avoids complex planning.

Transition: After backing up → ALIGN_TARGET_POSE

3. Navigation & Position Tracking

2D Odometry

The robot maintains an estimate of its position (x, y) and orientation (θ) using wheel encoder odometry combined with gyroscope feedback. Encoder deltas are converted to distances and projected onto the global coordinate system using trigonometry.

Heading Computation

heading = atan2(target.y - pose.y, target.x - pose.x) - pose.theta

The heading error is normalized and used to decide whether to perform a full turn or a smooth arc correction.

Why This Strategy Is Efficient

  • FSM structure avoids ambiguous behaviors
  • Time-based actions ensure mechanical reliability
  • Periodic realignment compensates for odometry drift
  • Smooth arc corrections maintain momentum
  • Simple obstacle recovery prevents deadlocks
