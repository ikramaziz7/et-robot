Algorithms & Strategy

1. State Machine (Main Control Algorithm)

The robot operates as a finite state machine, switching between different behavioral states based on sensor inputs and game conditions.

4. Supporting Algorithms

State Definitions

STARTUP: Initialize robot, move forward briefly to clear starting zone
ALIGN_TARGET_POSE: Calculate heading to target and rotate robot to face it
EXPLORE: Move toward target mineral while scanning for ores with color sensor
APPROACH_MINERAL: Stop when mineral detected by color sensor
PICKUP_MINERAL: Execute gripper sequence to collect ore
RETURN_HOME: Navigate back to home zone using position tracking
DROP_MINERAL: Release ore into collection box, increment to next target
AVOID_OBSTACLE: Back up and recalculate path when obstacle detected
END_MATCH: Stop all motors at game end

State Transition Logic

void update_state_machine(RobotContext *ctx) {
  switch (current_state) {

    case STARTUP:
      move_forward(START_SPEED)
      if (time > 2s) → ALIGN_TARGET_POSE

    case ALIGN_TARGET_POSE:
      heading = calculate_heading_to_target()
      if (obstacle_detected) → AVOID_OBSTACLE
      turn_to_heading(heading)
      if (aligned) → EXPLORE or RETURN_HOME

    case EXPLORE:
      move_forward(EXPLORE_SPEED)
      if (color_detected) → APPROACH_MINERAL
      if (obstacle_ahead) → AVOID_OBSTACLE
      if (touch_pressed) → AVOID_OBSTACLE
      if (time_to_realign) → ALIGN_TARGET_POSE

    case APPROACH_MINERAL:
      stop_motors()
      → PICKUP_MINERAL

    case PICKUP_MINERAL:
      execute_gripper_sequence()
      → RETURN_HOME

    case RETURN_HOME:
      move_forward(EXPLORE_SPEED)
      if (distance_to_box < 2.5cm) → DROP_MINERAL
      if (obstacle_ahead) → AVOID_OBSTACLE
      if (time_to_realign) → ALIGN_TARGET_POSE

    case DROP_MINERAL:
      release_ore()
      target_ore_index++
      → EXPLORE

    case AVOID_OBSTACLE:
      move_backward(AVOID_SPEED)
      → ALIGN_TARGET_POSE
  }
}

2. Position Tracking (2D Odometry)

The robot maintains real-time awareness of its position and orientation using encoder-based odometry combined with gyroscope feedback for accurate heading.

Coordinate System

Origin (0, 0): Robot's starting position in home zone
X-axis: Horizontal position (left/right movement)
Y-axis: Vertical position (forward/backward movement)
Θ (Theta): Robot heading from gyro sensor (calibrated at start)
Bearing: Absolute compass heading for global orientation reference

Position Update Algorithm

// Constants
WHEEL_DIAMETER = 3 cm
WHEEL_CIRCUMFERENCE = π × 3 cm

// Main loop (50 Hz update rate)
while (match_running) {
  // Read encoder changes
  get_encoder_deltas(&d_left, &d_right)
  
  // Convert encoder degrees to distance
  dist_left = (d_left / 360) × WHEEL_CIRC
  dist_right = (d_right / 360) × WHEEL_CIRC
  dist = (dist_left + dist_right) / 2
  
  // Get current heading from gyro
  gyro_angle = getGyroAngle()
  theta_rad = gyro_angle × (π / 180)
  
  // Update position using trigonometry
  pose.x += dist × cos(theta_rad)
  pose.y += dist × sin(theta_rad)
  pose.theta = gyro_angle
  pose.bearing = get_compass_value()
  
  update_state_machine()
  sleep(20ms) // 50 Hz
}

Encoder Delta Tracking

The system tracks incremental wheel rotations between update cycles:

get_encoder_deltas() calculates the difference between current and previous encoder positions for each wheel. This differential approach eliminates cumulative encoder overflow issues and provides smooth position updates. Static variables maintain encoder history across function calls.

Navigation to Target Coordinate

int heading_to_target_coord(Pose current, Pose target) {
  // Calculate vector to target
  dx = target.x - current.x
  dy = target.y - current.y
  
  // Calculate desired angle using atan2
  desired_rad = atan2(dy, dx)
  desired_deg = desired_rad × (180 / π)
  
  // Compute heading error
  diff = desired_deg - current.theta
  
  // Normalize to [-180, 180]
  return normalize_angle(diff)
}

Distance Calculation

Euclidean distance to any target position:
distance = √[(target.x - current.x)² + (target.y - current.y)²]

Used to determine when robot has reached destination (threshold: 2.5 cm for box position) and for real-time distance monitoring displayed every 50 update cycles.

Dual Heading System

Gyroscope (Theta): Relative heading for precise turns and odometry calculations. Calibrated to zero at startup.
Compass (Bearing): Absolute global heading (0-359°) for long-term orientation reference. Box bearing calculated as initial_heading + 180° to always know home direction.

This redundancy provides both precision (gyro) and global reference (compass) for robust navigation.

3. Motor Control & Turning Strategies

Gyro-Feedback Turning

Non-blocking turns: Instead of waiting for motor completion, the system uses gyroscope feedback to monitor turn progress in real-time:

start_turn(ctx, degrees, direction, speed) - Initiates turn and stores state
update_turn(ctx) - Called every cycle to check if target angle reached

When |current_gyro - start_gyro| ≥ target_degrees, motors stop and turn_active flag clears. This allows the state machine to continue processing during turns.

Arc Movement (Smooth Correction)

For gentle course corrections without stopping:

Principle: Reduce speed on inner wheel to create curved path
Implementation: If turning left, left_speed -= 40%, maintaining forward motion
Usage: Called every 3 seconds during EXPLORE and RETURN_HOME for drift correction
Benefit: Maintains momentum while adjusting heading, more efficient than stop-turn-go

Encoder Delta System

Tracks wheel rotation changes between update cycles using static variables to maintain state:

get_encoder_deltas(&d_left, &d_right) returns incremental rotation since last call. First call initializes baseline, subsequent calls return difference. This differential approach prevents integer overflow and provides smooth odometry updates at 50 Hz.

Resource Prioritization

Minerals are collected in a predefined sequence stored in mineral_positions[] array. The robot uses a target_ore_index counter that increments after each successful collection. This ensures systematic coverage of the arena and prevents revisiting already collected ores.

Obstacle Avoidance

Ultrasonic Sensor: When distance < 15cm, immediately stop and transition to AVOID_OBSTACLE state
Touch Sensor: Physical contact triggers immediate avoidance routine
Avoidance Behavior: Move backward at AVOID_SPEED (15% power), then return to ALIGN_TARGET_POSE to recalculate optimal heading
Recovery: After avoiding, robot realigns toward target and resumes mission

Periodic Realignment

To compensate for accumulated odometry errors, the robot periodically realigns itself:
Full Realignment: Every 10 seconds (ALIGN_TARGET_INTERVAL) - Complete stop and recalculate heading
Smooth Adjustment: Every 3 seconds (ALIGN_TARGET_ADJUST_INTERVAL) - Arc movement correction without stopping
This dual-strategy ensures both precision and efficiency during navigation.
